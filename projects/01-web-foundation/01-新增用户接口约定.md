# 新增用户接口约定

状态：正式 POST /api/users 已实现并验证，已同步Postman。新增201、重复409、字段或JSON错误400均通过真实HTTP验证，成功数据保留。

## 目标与请求

创建一条用户记录。此时不是注册或登录，不涉及密码和权限。

```http
POST /api/users
Content-Type: application/json
```

```json
{
  "username": "qiubai",
  "nickname": "秋白"
}
```

- username：必填，3～32 位，仅允许英文字母、数字、下划线；不自动去除空格或修改大小写。不区分大小写判重，保留原始合法输入。
- nickname：必填，不能全是空白；长度按 Java String 的 UTF-16 代码单元计数，范围 1～50，部分表情会计为两个长度单位。本阶段不自动裁剪首尾空格。
- id、createdAt 由服务端生成或读取，客户端无需提交。
- 接口输入将使用 CreateUserRequest，输出使用 UserResponse；数据库记录使用 User，三者职责不同。

## 创建成功

HTTP 状态码 201 Created。下面的 ID 和时间仅为示例，不保证实际编号从 1 开始。

```json
{
  "code": "SUCCESS",
  "message": "用户创建成功",
  "data": {
    "id": 3,
    "username": "qiubai",
    "nickname": "秋白",
    "createdAt": "2026-11-10T12:00:00"
  }
}
```

- code 是应用结果代码，与 HTTP 状态码是两个层次。
- message 是给人阅读的说明；调用方按状态码和 code 判断，不依赖说明文字。
- data 是业务数据。创建时间由数据库生成，再查询取得实际值；不能用应用当前时间冒充数据库已保存值。
- createdAt 对应 LocalDateTime，示例无时区偏移，不表示 UTC 时间。

## 失败约定

| 情况 | HTTP 状态码 | code |
| --- | --- | --- |
| 字段缺失、格式不合法、空请求体或 JSON 格式错误 | 400 | INVALID_ARGUMENT |
| 用户名已存在，包括仅大小写不同 | 409 | USERNAME_ALREADY_EXISTS |
| 未预期的内部错误 | 500 | INTERNAL_ERROR |

```json
{
  "code": "USERNAME_ALREADY_EXISTS",
  "message": "用户名已存在",
  "data": null
}
```

内部错误对外返回通用说明，详细原因记录在服务端日志中。唯一约束是并发情况下判重的最终保证，不把所有数据库错误都当作用户名重复。
不把所有失败统一返回 HTTP 200。

## 验收

1. 合法输入返回 201，数据库中只有一条对应记录，返回数据与保存值一致。
2. 重新提交相同用户名返回 409，不新增第二条记录。
3. 提交仅大小写不同的同名用户名也返回 409。
4. 用户名含空格、太短、昵称全为空白等输入返回 400，不插入记录。
