# 02：按 ID 查询用户接口约定

状态：已实现并通过真实HTTP验收。

```http
GET /api/users/{id}
```

无请求体。id必须是Long范围内的正整数。

- 已存在：200，code=SUCCESS，data包含id、username、nickname、createdAt。
- 合法ID但无对应用户：404，code=USER_NOT_FOUND，data=null。
- 0、负数、非数字或超出Long范围：400，code=INVALID_ARGUMENT，data=null。

`@GetMapping("/{id}")` 与类级 `/api/users` 组合路径。
`@PathVariable("id") Long id` 从路径读取并转换为Long。
非数字或超范围在转换阶段触发MethodArgumentTypeMismatchException，由全局异常处理器返回400；0和负数能转换为Long，但业务层拒绝。
该方法不接收JSON请求体，不需要为Long参数添加请求DTO的@Valid。

本机可以查询ID4、6、10或本次验收新增的15。新环境先通过新增接口创建，再使用实际返回的ID，不假定不同数据库具有相同编号。

成功响应示例：

```json
{
  "code": "SUCCESS",
  "message": "查询成功",
  "data": {
    "id": 4,
    "username": "learn_user_01",
    "nickname": "学习用户一号",
    "createdAt": "2026-11-10T12:58:36"
  }
}
```
