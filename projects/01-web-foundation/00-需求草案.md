# 01：用户基础接口——需求草案

状态：新增与按ID查询两个接口均已完成并验收，见03-模块归档.md；本文件保留原需求与学习路线。

## 业务目标

建立两个接口：新增用户、按 ID 查询用户。通过小功能理解 HTTP → Controller → Service → Mapper → MySQL 的链路。

## 建议范围

- 新增用户：输入用户名和昵称，成功后返回 ID、用户名、昵称、创建时间。
- 用户名建议限制为 3～32 位英文字母、数字、下划线；不允许重复，大小写视为相同。
- 昵称必填，按Java字符串长度计算为1～50个UTF-16代码单元，不能只包含空白。
- 按正整数 ID 查询；不存在时返回明确的未找到响应。
- 第一阶段的用户只是练习业务记录，不具备登录能力。
- 登录、密码存储、权限和缓存在后续独立步骤加入。

## 验收场景

1. 创建一条合法用户记录，能按返回的 ID 查询到。
2. 用户名为空、格式不合法或昵称为空白时，返回参数错误。
3. 重复用户名不能创建第二条记录。
4. 查询不存在的 ID 时返回未找到。

## 已确认的字段

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| id | 用户唯一编号 | 数据库自增主键 |
| username | 用户名 | 唯一约束 |
| nickname | 昵称 | 展示名称 |
| created_at | 创建时间 | Java 字段命名为 createdAt |

表结构已按讨论结果执行并验证；SQL见infra/mysql/002-create-app-user.sql。
