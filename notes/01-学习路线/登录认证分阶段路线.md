# 登录认证分阶段路线

约定：主题使用独立子项目，保留不同方案供对照；每次只实现当前一步，不预先生成完整模块。具体目录名在开始该项目时确定。

## 当前：基础 Web 与用户数据

01-web-foundation 只做新增、查询用户、参数校验、数据库读写、统一响应和异常处理。
这里的“新增用户”不是注册，没有密码字段和身份认证。新增和按ID查询HTTP接口已完成验收，后续登录单独建项目。

## 阶段一：单实例 Session 登录

- 独立练习注册、密码哈希验证、登录、查询当前登录用户、退出与会话超时。
- 先用服务端本地会话理解 Session 与 Cookie；基础版也不保存明文密码。
- 验证未登录访问、密码错误、登录后访问、退出后访问和会话过期。
- 观察服务重启或多实例时本地会话的限制，不把该方案的实验行为推广到所有部署配置。

## 阶段二：Redis 共享会话

- 复用身份认证知识，单独练习将服务端会话保存到 Redis。
- 重点是多实例共享登录态、TTL、续期、退出失效和 Redis 故障行为。
- Cookie/会话 ID 可以标识 Redis 中的会话，不要求引入 JWT。
- 使用独立练习实例和 lab:项目前缀，不影响本机其他项目。

## 阶段三：JWT 访问令牌

- 单独练习令牌签发、签名验证、有效期、声明与访问受保护接口。
- JWT 是令牌格式；常见签名 JWT 的载荷可以读取，签名不等于加密。
- 理解“验证签名通过”还需配合有效期、签发方、受众等适用检查。
- 讨论客户端删除令牌与服务端立即撤销令牌的区别。
- 此阶段不强制使用 Redis，先观察已有访问令牌在退出后的行为。

## 阶段四：JWT 与 Redis 配合

- 根据需求练习刷新令牌状态、轮换、撤销、多端会话或踢下线。
- 明确 Redis 保存哪些状态、每次请求是否查询 Redis、故障时怎样处理。
- 使用 Redis 保存认证状态后，不将整体方案描述为完全无状态。

## 阶段五：多应用单点登录

- 建立多个应用与认证中心，学习成熟协议中的登录、回调、票据或令牌与退出流程。
- 单点登录不等于让多个应用随意共用一个 JWT 密钥。

这些方案解决不同需求，不以使用组件更多作为“更高级”的判断标准。
