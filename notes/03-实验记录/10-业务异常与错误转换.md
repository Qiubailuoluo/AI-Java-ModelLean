# 业务异常与错误转换

新增 common/exception/BusinessException.java，调整 UserServiceImpl.create 的重复键处理；尚无全局异常处理器或业务 Controller。

## 为什么增加业务异常

DuplicateKeyException 描述数据库唯一键冲突。业务调用方需要更明确的含义，例如 USERNAME_ALREADY_EXISTS 与“用户名已存在”。
当前 SQL 不提交主键，用户输入涉及的唯一约束只有 username，因此把此插入处的 DuplicateKeyException 转换为用户名重复。以后新增其他唯一字段或改用客户端主键，需要重新检查这项假设。
不捕获所有 Exception 并统一叫“用户名重复”；连接失败、SQL 错误等必须保留各自问题。

## BusinessException 逐项解释

- extends RuntimeException：继承 Java 的运行时异常类型；当前 Spring 事务默认会因向外抛出该类型异常而回滚。
- private final String code：业务错误代码，例如 USERNAME_ALREADY_EXISTS；不等于 HTTP 状态码。
- @Getter：为 code 生成 getCode()；getMessage() 是从异常父类继承的方法。
- 两个同名构造器：参数列表不同，称为构造器重载。
- super(message)：调用父类构造器，设置异常说明。
- Throwable cause：携带底层异常原因。Throwable 是 Java 异常/错误体系的基类。
- super(message, cause)：保留说明和原始异常链，后续可在服务端日志定位数据库问题。

## Service 转换

try 中执行插入；catch 仅处理 DuplicateKeyException；throw new BusinessException 抛出业务错误并终止正常流程。
异常被转换后仍然向调用方抛出，并非捕获后忽略，所以事务仍能按规则回滚。
BusinessException 不会自动创建 JSON 或设置 409；下一步由全局异常处理器在 HTTP 请求链路中完成映射。底层异常链不应直接序列化返回客户端。
