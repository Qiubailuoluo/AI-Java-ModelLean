# 全局异常与统一响应链路

源码：projects/01-web-foundation/src/main/java/com/qiubai/lab/web/common/exception/GlobalExceptionHandler.java。

## 本轮范围

增加全局异常处理器，把 Spring MVC 请求链路中的异常转换成 ApiResponse 和 HTTP 状态。
还没有正式业务 Controller。本次验证入口仅存在于 work/database/HttpErrorDemo.java，在临时进程中显式注册，未加入业务源码或 Postman；验证结束已关闭服务器和应用上下文。

## 两条链路

业务冲突：请求 → Controller → Service 事务代理 → Mapper → 数据库唯一键冲突 → BusinessException → 事务回滚并继续抛出 → Spring MVC 选择全局处理方法 → HTTP 409 + ApiResponse JSON。

参数错误：请求 → JSON 转对象 → @Valid 校验失败 → MethodArgumentNotValidException → 全局处理方法 → HTTP 400 + ApiResponse JSON。此时不进入业务方法。

## 注解和类型

- @RestControllerAdvice：Spring MVC 控制器增强，作用于控制器请求链路，返回对象按响应体处理；不是捕获所有线程、定时任务或启动阶段异常。
- @ExceptionHandler(X.class)：选择处理某类异常的方法，更具体的异常匹配优先，不按源码方法先后顺序匹配。
- @Slf4j：Lombok 生成日志对象 log；内部异常及原因记录在服务端，不直接返回客户端。
- ResponseEntity<ApiResponse<Void>>：ResponseEntity 承载 HTTP 状态、响应头、响应体；ApiResponse 承载 code/message/data；Void 表达此处没有业务数据，data 实际为 null。
- body(...)：设置响应体对象；Spring MVC 使用消息转换器把它序列化，当前 JSON 由 Jackson 处理。

## 当前映射

| 异常或情形 | HTTP | code |
| --- | --- | --- |
| BusinessException，代码为 USERNAME_ALREADY_EXISTS | 409 | USERNAME_ALREADY_EXISTS |
| MethodArgumentNotValidException | 400 | INVALID_ARGUMENT |
| HttpMessageNotReadableException | 400 | INVALID_ARGUMENT |
| 未预期异常或未约定映射的业务代码 | 500 | INTERNAL_ERROR |
| Spring MVC 已通过 ErrorResponse 表达的错误 | 保留其状态和头 | HTTP_ERROR |

参数校验目前只返回一条字段错误，不保证约束报错顺序。JSON 解析失败等返回通用提示，不回传内部解析细节。
ErrorResponse 是 Spring 的错误描述接口，不是我们的 ApiResponse；用它保留 404、405 等状态及 Allow 等头，避免兜底误报 500。
此阶段尚未实现路径参数约束等其他校验方式；引入具体接口时按实际异常类型补充，不声称当前已覆盖所有校验场景。

## HTTP 实测

Maven compile 通过。临时 HTTP 服务由操作系统分配空闲端口，仅绑定 127.0.0.1，八组请求均通过：

1. 已保留用户 learn_user_01 的大写用户名冲突 → 409。
2. 非法用户名与空白昵称 → 400。
3. 损坏的 JSON → 400。
4. 空请求体 → 400。
5. 未预期运行时异常 → 500，隐藏内部说明。
6. 未约定的业务代码 → 500，隐藏内部说明。
7. 不存在的路径 → 404，使用统一响应。
8. 错误 HTTP 方法 → 405，保留 Allow: POST。

检查了响应具有 code/message/data、data 为 null，不携带 cause、trace 或内部测试详情。
没有成功插入新用户，既有练习记录保留；失败的重复插入可能消耗自增编号。
